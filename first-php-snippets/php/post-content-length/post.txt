[b]1. [u]Metoda Apache[/u][/b]

[b]Situatia:[/b]
Se doreste ca procesarea scriptului PHP sa nu mai aiba loc daca apare "conditia".

[b]Descriere:[/b]
Directiva LimitRequestBody permite intreruperea procesarii cererii HTTP in cazul in care aceasta depaseste o anumita limita.
Codul HTTP returnat este 413, "Request Entity Too Large".
Impreuna cu directiva ErrorDocument permite afisarea unui mesaj (personalizat) in cazul in care apare "conditia".
Consider ca reprezinta o solutie foarte buna pentru protejarea generala a scripturilor PHP.

[b]Exemplu:[/b] (fisier .htaccess)
[code]
# Nu permite o cerere mai mare de 2MB
LimitRequestBody 2097152
# Afisarea unui mesaj personalizat pentru codul de eroare curent
ErrorDocument 413 /calea/catre/directorul/cu/mesajul.htm
[/code]

[b]Avantaje:[/b]
Scriptul PHP nu este afectat in nici un fel. Deoarece nu va mai fi procesat, nu mai este generat nici warning-ul.
Nu necesita configurari sau module suplimentare in Apache, functioneaza cu setarile default.
Se poate personaliza mesajul de eroare aparut.

[b]Dezavantaje:[/b]
Necesita serverul web Apache, cel putin versiunea 1.3.2. Pentru cei ce folosesc IIS nu stiu daca exista ceva asemanator.
Personalizarea mesajului de eroare este de fapt "generala" pentru WebSite-ul / directorul respectiv, nu pentru fiecare script PHP in parte.
Cand se stabileste limita admisa, trebuie avut in vedere faptul ca LimitRequestSize se refera la toata cererea HTTP nu doar la partea de POST.

[b]Resurse:[/b]
LimitRequestBody: [url]http://httpd.apache.org/docs/1.3/mod/core.html#limitrequestbody[/url]
ErrorDocument: [url]http://httpd.apache.org/docs/2.0/mod/core.html#errordocument[/url]
Coduri HTTP: [url]http://www.w3.org/Protocols/rfc2616/rfc2616-sec10.html[/url]

[b]2. [u]Metoda PHP[/u][/b]

[b]Situatia:[/b]
Se doreste procesarea scriptului PHP chiar daca apare "conditia", si nu reprezinta o problema warning-ul generat.

[b]Descriere:[/b]
Functia error_get_last() afiseaza informatii despre ultima eroare PHP aparuta.
Folosind aceasta functie, putem verifica daca exista warning-ul nostru si sa actionam corespunzator.
Desi nu este prea eleganta, consider ca este cea mai buna solutie.

[b]Exemplu:[/b] (fisier php)
[php]
<?php
/**
 * Daca functia error_get_last exista, 
 * variabila $error va contine ultima eroare aparuta
 */
$error = function_exists('error_get_last') ? error_get_last() : NULL;
/**
 * Daca avem o eroare si este cea pe care o cautam...
 */
if(is_array($error) && (FALSE !== strpos($error['message'], 'POST Content-Length of')))
{
  /**
   * Facem ceva
   */
   trigger_error('Fisierul este prea mare', E_USER_ERROR);
}
?>
[/php]

[b]Avantaje:[/b]
Intr-un fel se poate de fapt "prinde" eroarea, nu in sensul ca nu mai apare, ci in sensul ca putem verifica prezenta ei si actiona corespunzator.
Se lucreaza direct in PHP, nu este nevoie a se umbla la setarile serverului.
Se poate verifica daca apare "conditia" pentru scriptul PHP curent si se poate actiona corespunzator.

[b]Dezavantaje:[/b]
Necesita cel putin versiunea 5.2 a PHP
Va fi generat warning-ul.
Variabilele $_POST si $_FILES sunt goale, desi cererea HTTP exista (se poate retransmite formularul cu refresh din browser).
Este necesar sa nu existe alta eroare aparuta in urma executiei scriptului PHP.

[b]Resurse:[/b]
Functia error_get_last(): [url]http://www.php.net/error_get_last[/url]
